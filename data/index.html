交通燈資料集

香港交通相機預警（com.nicfox.hktrafficcamera）地圖圖層所使用的資料

這是甚麼

全港 7,707 個交通燈頭的位置，來源為 OpenStreetMap 的 highway=traffic_signals 節點。App 用它在地圖上畫出所有燈位， 並可篩選出「有紅燈相機的燈位」（815 個）。

為甚麼不用政府資料

香港運輸署沒有「全港交通燈位置」的開放資料集。 data.gov.hk 的 hk-td-tis_15-road-network-v2 內只有 「Intersection point of two centerlines」（所有路口中心點，沒有燈號屬性）， 而紅燈相機資料只有 211 個路口。所以要覆蓋全港，OSM 是唯一來源。

兩份獨立資料互相印證：211 個紅燈相機（政府資料） 全部能在 27 公尺內找到對應的 OSM 燈位 —— 中位 13m、P90 20m、最大 26.7m。 這也是「只看有相機的燈位」這個篩選可以成立的前提。

檔案

檔案大小說明
traffic_lights.bin 69,377 bytes 二進位格式，App 內建使用；差值編碼，座標精度 1e-5 度
traffic_lights.json 314,441 bytes 同一份資料的可讀版本，方便查閱與再利用

格式

traffic_lights.bin

magic  "HKTL"                     4 bytes
ver    u16 little-endian          必須為 1
scale  float32 little-endian      固定 1e5
count  u32 little-endian          點數
count × ( dlat i32, dlng i32 )    差值編碼，已按 (lat, lng) 升序排列
count × flags u8                  見下

flags 位元定義：

位元數值意義數量
bit 00x01車輛燈號7,353
bit 10x02行人過路燈2,650
bit 20x0460 公尺內有紅燈相機815

同一個燈頭可以同時是車輛燈號與行人過路燈（同一支燈柱既管車也管人）， 所以三個位元不是互斥的。沒有 crossing 標籤的 highway=traffic_signals 依 OSM 慣例判為車輛燈號。

traffic_lights.json

{
  "source":  "OpenStreetMap contributors",
  "licence": "ODbL 1.0 — https://opendatacommons.org/licenses/odbl/1-0/",
  "count":   7707,
  "lights": [ { "lat": 22.219342, "lng": 114.212818, "f": 1 }, ... ]
}

f 與上面的 flags 位元定義相同。

已知限制

  • 位置為 OSM 貢獻者測繪的燈頭節點，並非運輸署官方測量座標，個別位置可能有數公尺偏差。
  • 資料隨 OSM 編輯而變動，本檔為某一時點的快照。
  • 燈號的當前狀態（紅／黃／綠）不在此資料內，亦不提供即時燈態。

重新產生

本檔由 App 專案的 tools/fetch_traffic_lights.py 產生：

python3 tools/fetch_traffic_lights.py --dump-json traffic_lights.json

腳本會查詢 Overpass API、分類燈號、與紅燈相機做 60m 空間關聯，然後輸出上述兩種格式。
